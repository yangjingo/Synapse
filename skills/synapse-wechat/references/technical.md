# 将技术材料写成公众号文章

先决定公众号读者已有的背景。一份机制很多的技术长文可以选一条能说明现实差异的主线。开篇用输入、瓶颈或现场例子给足理解所需的背景，再给当前判断。后面只保留支撑该判断的机制、一个具体例子及必要边界。

- 有源稿时保留可核查的主张、数值、指标口径与来源链接。跨模型或跨负载的引申用条件限定。
- 紧跟读者能追踪的对象与动作。首次出现的术语用一句话定位。源码可放在对应说法后的链接，由读者选择深度。
- 对论文，保留贡献、基线、证据与适用范围。对项目复盘，保留作者当时的选择、反馈和后来发生的变化。材料需要先做深度核验时，调用 `synapse-tech-blog` 的相应研究场景，再回到本 reference 编辑。
- 技术图优先用上下阶段或左右并列对照。来源图保留比例与标注。若输出为单栏 HTML，按 [layout.md](layout.md) 检查阅读和复制。
