# 技术复盘

当作者、团队的实际选择和时间线决定文章价值时使用。先根据材料提取当时的目标、可用信息、决策、观察、结果、代价和后来改变的行动。把当时的判断和目前的解释并列核对。

- **项目复盘**从一个具体决策或故障开始，说明选择如何产生、回退是否奏效、下次检查哪一个信号。
- **研究回顾**沿假设 → 实验 → 观察 → 改判 → 后续验证展开。方案、样机、上线与真实使用证据分别表述。
- **历程式复盘**以不断变化的技术问题推进时间线。每个阶段优先选一个有证据的技术变化、由它产生的问题、尝试和改变后的判断。

让具体处境先于原则。选择、后果和修正至少形成一次完整因果链。作者亲历、公开来源、编辑重述和推断需要能辨认。只引用材料中真实的对话，不补写未确认的动机、数字、客户信息或结果。缺关键材料时保留 `待补充`。公开稿按用户授权使用素材。

技术说明只展开到同行能理解当时为何这样做。正文保留代价、失败假设和适用边界。收尾给一个下一次会怎样判断或行动的可核验变化。需要出图时按 [image.md](image.md) 画因果或前后对照。
