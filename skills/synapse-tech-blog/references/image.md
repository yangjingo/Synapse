# 文章技术插图

## 先定读图顺序

每张图回答一个问题。先写出读者要看到的变化或关系，找齐对应的组件、状态、数据和来源，再画出主路径、分支和对照结构。

**讲系统组成、组件职责或跨实例交接时，优先用架构图。** 需要解释等待、重试或先后依赖时，再用时序图展开。

## Warm Minimal Technical Diagram

- **配色。** 画布 `#EEEDE4`，内容区 `#F9F8F3`，普通节点 `#EDEDE4`，核心节点 `#DBD9CF`，统一暖灰边框和箭头 `#99998F`。正文标签使用深灰无衬线字体，模块名适度加粗。同一色阶在各图承担相同语义，仅在必须区分状态或边界时引入低饱和强调色。
- **线条。** 主路径用实线，次要或可选路径用较轻的线条。条件或独立子系统可用浅底虚线边界。连接使用细线和开放式箭头，箭尖落在接收组件边缘。颜色与线型一旦用于区分某种关系，跨图保持同义。
- **密度。** 默认 16:9 横版，四周留安全边距。节点通常最多两行，组件名、动作、状态和数值以短英文标签呈现。因果解释与收益放在图注。画面保持扁平，标题和图例只在帮助读图时使用。省去渐变、阴影、纹理和装饰图标。

| 图类型 | 默认布局 |
| --- | --- |
| 架构图 | 主模块居左，依赖组件居右。共享资源放在路径汇合处，只画一次。 |
| 流程图 | 主路径单向推进，条件分支放在侧面。 |
| 对照图 | 左右等宽，比较对象与共同步骤对齐。真正共用的入口或出口可各画一次。 |
| 时序图 | 参与方横向排列，事件从上到下推进。 |
| 边界图 | 多条状态轨道共用一条坐标轴，高亮关键状态或恢复点。 |

[五类绘图样例](../examples/warm-minimal-technical-diagrams.html)可按博客正文宽度预览。

用位置、线条或强调色突出主路径和关键结果。对齐同类元素，同组节点靠近，组间留出更多空白。没有事件的泳道留白。对称用于建立对应关系，额外步骤保留独立空间。

### 正文尺寸排版

先按约 700 CSS px 的博客版心看图，再决定字号和线宽。以下是样例使用的起点，按实际版心和标签长度调整。

| 元素 | 在正文宽度下的检查 |
| --- | --- |
| 字号 | 组件名约 16 px、字重 600，常规标签约 14 px、字重 400，短状态词和刻度约 13 px。缩小时优先删解释、拆图或提供放大。 |
| 边距与间隔 | 外边距从图宽约 4% 起。组间距大于组内间距。走线区还要留出箭头长度和标签高度，保证线头和文字各有空间。 |
| 主线与次线 | 主线约 2 px。次线用相同色相、较细的线和较低的对比度。没有色彩时仍能靠线型、位置和符号读图。 |
| 注释与放大 | 动作标签贴近对应线段，避开折角、交点、箭头尖和容器边。窄屏保留完整构图，图内细节可通过点击放大查看。 |

## 架构图

- **布局。** 先画实例、进程或子系统边界，再摆组件。入口在上方或左侧，实例内部按职责分层。并列实例的同类组件放在同一高度，节点尺寸保持一致。共享入口或资源放在连线自然汇合的位置。
- **风格。** 用浅色区域区分实例，组件框保持同一种轮廓。默认暖象牙底和深墨字，细线画常规连接。将强调色留给文章要讲的数据流或关键交接，控制、数据和响应各自选定线型并保持同义。图内只留真实组件名、动作名和传递物。
- **间隔。** 同层按统一网格对齐，同组等距。组间留的空间大于组内间距，跨实例的空白带应放得下平行箭头、箭头尖和短标签。标签靠近对应线段，放在线旁的空白处。画面拥挤时先减少标签和折点，再拆出局部细节。
- **连接点。** 写清每条边的起点、终点和传递内容。箭头从发起方组件框的边缘出发，箭头尖落在接收方组件框的边缘。层间连线优先接上下边，跨实例连线优先接两框相向的侧边。去程和回程用不同的接入点及平行线，优先直线，转折用直角并绕开节点和文字。发起请求、传回字节、返回响应的方向分别核对。

## 绘图提示词

先填通用提示词，再追加一个与文章问题对应的构图片段。用源码或材料里的具体名称填空。

### 通用提示词

```text
为技术博客画一张【图类型】，回答【唯一的读图问题】。
依据【来源和版本】，使用【真实对象、状态和数值】。读图顺序是【起点 → 关键变化 → 结果】。
用【相对位置、箭头、区间或对齐线】表达主要关系。先让读者看到【主路径或关键差异】。
同级元素对齐，同组等距。组间留出更大的空白给连线和短标签。
默认横版 16:9，四周留安全边距。画布 #EEEDE4，内容区 #F9F8F3，普通节点 #EDEDE4，核心节点 #DBD9CF，细边框和开放式箭头 #99998F。深灰无衬线字，模块名适度加粗。同一语义用同一色阶或线型，需要区分状态时才引入低饱和强调色。
图内只留必要的英文标签、数值和单位。解释句放在图注。按博客实际显示尺寸核对标签、走线、裁切和主次。
```

### 架构图提示词

```text
画出【实例、进程或子系统】的边界。主模块居左，依赖组件居右。把【共享入口或资源】放在连线汇合处，只画一次。并列实例的同类组件同高对齐。
按【起点组件及边缘 → 终点组件及边缘｜传递内容｜短英文标签】逐条连接。
层间连线接上下边，跨实例连线接两框相向的侧边。箭头尖贴接收方框边。
去程和回程用独立接入点和平行线。优先直线，必要时用直角折线绕开节点。标签放在线旁的空白处。
分别核对调用、返回数据和响应的方向。用强调色突出【读者应先追踪的一条路径】。
```

### 其他构图片段

| 场景 | 可直接追加的提示词 |
| --- | --- |
| 前后状态或覆盖范围 | 上下画【前状态】和【后状态】。同一角色或 token 位置保持在同一列。用条带的起止和颜色标出【保留、失效、重算或新增的范围】。 |
| 左右方案或存储布局对照 | 左右画【方案 A】和【方案 B】。先对齐共同入口、组件和输出。同一对象换位置时沿用同一颜色、形状或编号。区间对照共用量尺，用同一位置标出边界。额外步骤在所在一侧单独留空间。 |
| 请求时序与回环 | 为【参与方】各画一条竖向泳道，事件从上到下。跨列箭头标【动作或传递物】。循环框只围住参与的泳道和动作，条件写在框边。 |
| 路由选择 | 把【输入、路由和输出】沿主轴排开，【候选节点】等距排列。用实线标出这次经过的分支，较轻虚线标出其他候选。 |
| 校验与共同边界 | 让【候选位置】与下方【各组件的校验结果】逐列对齐。用条带表达连续覆盖，用圆点表达离散 checkpoint，用一条纵向高亮线指向【共同可用的边界】。 |

## 让图形表达关系

- 图内保留能帮助定位或读数的短英文标签，例如组件名、动作名、状态、数值、坐标轴和单位。完整的因果解释、适用条件和结论放到图注或对应正文。
- 画面拥挤时先移出重复说明，再考虑拆成总览与放大细节，或拆成采用相同坐标的对照图。每个面板保留清晰的读图顺序和可读字号。
- 技术长文新图默认 16:9 横版，核对实际像素。适用本节视觉规范时，颜色和线型跨图保持同义。用户指定载体比例和项目 `DESIGN.md` 优先。连续研究页读[论文解读](paper.md)。
- 架构图采用真实模块或源码符号。证据图保留原始比例、标注、单位和归因。重绘要能回到原始图号与链接，实验图注明基线、口径和条件，假设性示意明确标记。

## 交付前检查

- [ ] 第一眼能找到主路径、比较对象或关键边界。
- [ ] 同一共享组件只画一次。
- [ ] 标签与连接线互不遮挡，箭头接到对应组件的边。
- [ ] 组间距大于组内间距。
- [ ] 每种颜色和线型有明确且一致的含义。
- [ ] 移除解释性文字后，主要逻辑依然成立。
- [ ] 缩到文章正文宽度后，标签、箭头和关键刻度保持清晰。

对照图核对量尺。时序示意按纵向位置表示先后，需要表达耗时时标出实际刻度。图注用 `Figure N: description` 作短标题，再交代意义和来源。图片 alt 描述画面，并核对图、图注和正文里的组件名、数字和方向。

离线 HTML 可用 HTML/CSS 绘制流程、时间轴和证据图。独立可编辑文件使用 [Excalidraw 工作流](../workflows/excalidraw/WORKFLOW.md)，动效使用 [Talk Slides 动画导出参考](../../synapse-talk-slides/workflows/animation/WORKFLOW.md)。生成栅格图时，Synapse 默认使用 Codex imagegen。保留渲染源或提示词于项目素材，交付完成的图片与文章。
