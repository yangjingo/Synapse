# 文字结构

## 用观点写标题

文章和章节标题默认用陈述句表达观点。标题写出主体和关键判断，让读者扫完目录就能看出论证怎样推进。「参考资料」等功能性标题可以直接标明用途。用户给定的文章标题按原题处理。

把「前缀命中了，为什么还要回放窗口？」改成「全局 KV 命中后，局部窗口仍可能需要回放」。本节首段从第二轮请求的缓存状态引出回放问题。

## 用 QCSA 组织章节

用 QCSA 规划一个章节。起草时先定 Q，再找出相关的 C 和 S，最后写出 A。

| 要素 | 写作时要回答的事 |
| --- | --- |
| Q · Question | 本节要解决的具体问题是什么 |
| C · Complication | 哪个约束、变化或现象使这个问题值得讨论 |
| S · Situation | 读者需要知道哪些场景、参与方和已有状态 |
| A · Answer | 本节给出的技术判断是什么，在哪些条件下成立 |

成稿首段先落到一个具体场景。沿用同一个例子时，可以接住上一节刚得到的结果，再顺着新出现的限制向前推进。遇到实现与预期不同的地方，也可以用这个差异说清本节的问题。问题可以写成陈述句。直接问句适合请求转折、读者需要做判断或某个结果值得停下来琢磨的地方。

在开头的场景和卡点之后，用一个加粗的完整句给出本节的回答。句子写出具体动作、条件或判断，读者扫读粗体时能直接知道这一节解释了什么。需要展开的机制、证据和验证方法放在其后。附录提供实际操作时，可以在步骤前加粗一条决定何时采用这套做法的判断。连读相邻章节的开头，检查上一节的结果怎样把读者带到下一节。

例如，「Agent 在旧前缀后追加 256 个 token。缓存池找到了全局 KV，短时 DRAM 池却已经回收了 Encoder 的 SWA。推理引擎还缺一份局部状态，才能继续处理这段新输入。」下一段给出回答。**推理引擎复用全局 KV，并重放前缀尾部来重建 Encoder 的 SWA。** 之后再交代回放范围、近似边界和验证指标。

场景、卡点与问题的关系可以参照 [Barbara Minto 对 SCQ 的说明](https://www.barbaraminto.com/)。

## 写完整句

摘要、正文和图注中的每个叙述句都要写清主语和谓语。动作涉及对象时，把宾语写全。状态句要交代对象与状态，例如「请求已完成」。

- 主体变化时，直接写出组件、团队或对象的名称。一个主体执行连续动作时，同一句可以共用一个主语。
- 多个主体分别执行关键动作时，可以按动作拆成短句。每个句子都要写出实际执行者。
- 标题、表头和图里的组件标签可以用短语。正文列表里用于解释机制或报告结果的条目仍要用完整句。

把「第二轮请求到来后，找到已有 KV，再恢复状态」改成「第二轮请求到来后，缓存管理器查找已有的 KV。推理引擎根据命中的 KV 恢复请求状态。」实际写作时，按具体系统的职责确定主语。

## 把引用写进句子

先找出需要核验的主张，再决定谁做了什么、读者该点开什么。论文名、工作名、函数名和运行记录可以充当主语、宾语或依据，也可以链接到动作中具体的可核验对象。比如，「Worker 根据〔GitHub Webhook 投递指南〕中的投递 ID 识别重发」把链接放在规则出处上。「维护者检查〔Windows Desktop 基线运行〕中的安装步骤」把链接放在被检查的记录上。

遇到「V1 调度器按 token 分配预算。〔参考资料〕」这样的段落，先改写归因。「[vLLM V1 的调度器设计](https://vllm.ai/blog/2025-01-27-v1-alpha-release)使用固定的 token 预算，并在每步为各请求分配 token。」如果同一段随后讨论另一个系统，就为那个系统另写主张和来源。一条运行链接放在它能证明的结果旁，一条接口文档放在它说明的能力或限制旁。一个段落有多份证据时，可拆句分配来源。

正文用能识别对象的短名，链接到原论文、官方文档、固定版本的实现或具体运行。精确到章节、代码行或工作流运行时，打开目标确认该处真的支持主张。需要权限时在附近说明读者到哪里取得访问。同一来源已清楚归因且上下文连续时，可沿用短称。文末按需提供完整书目、独立导航或复现材料。

按证据选择动词。论文「提出」机制，源码「实现」某步骤，运行记录「显示」某提交的结果，外部文档「说明」平台具备的能力。本文把外部机制用于自己项目时，用「我会」「本文设计」「拟验证」交代推断或方案。作者自述的观察保留归因，待核实的证据写明缺口。

## 参考同行的写法

| 原文 | 可以复用的写法 |
| --- | --- |
| [Anthropic · Effective harnesses for long-running agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) 和 [Scaling Managed Agents with stable interfaces](https://www.anthropic.com/research/managed-agents) | 从会话中断等失败切入，把先前的工作放进叙述，再交代下一次会话靠什么制品恢复。讲接口演进时，给出设计成立的条件和后来改变的假设。 |
| [vLLM · PagedAttention](https://vllm.ai/blog/2023-06-20-vllm) 和 [vLLM V1](https://vllm.ai/blog/2025-01-27-v1-alpha-release) | 把比较对象写进基准句，说明硬件、模型、请求和指标。机制段落可沿一个对象解释它如何跨组件流动，读者据此理解结果的适用范围。 |
| [SGLang · RadixAttention](https://www.lmsys.org/blog/2024-01-17-sglang/) 和 [Unified Radix Cache](https://www.lmsys.org/blog/2026-08-11-unified-radix-cache) | 用一个请求序列把缓存状态变化、图和操作关联起来。出现共享对象时，进一步说明各组件在哪个条件下能复用，与实现链接对应。 |
| [Lil’Log · LLM Powered Autonomous Agents](https://lilianweng.github.io/posts/2023-06-23-agent/) 和 [Contrastive Representation Learning](https://lilianweng.github.io/posts/2021-05-31-contrastive/) | 先按问题组织概念，再以工作名配作者归因，说明一项工作如何解决当前问题。相邻工作可以沿同一个变量比较，正文保留必要连接，书目承担查找功能。 |

审稿时读出含链接的句子，检查锚文本能否直接融入语法，读者能否知道点击目标与本句的关系。检查段末、表格单元格和列表项是否残留孤立的来源。链接处在句尾时也应由句子的动作管辖，例如「维护者核对了〔本次 Actions 运行〕」。

## 统一术语

中文稿沿用同行常用的英文、缩写或成熟中文术语，例如 `logits`、`LM head`、`KV Cache`、前向计算、交叉熵。读者可能不熟悉的术语首次出现时，用一句完整的话说明它在当前流程里做什么。例如，「LM head 把每个位置的 hidden state 投影成整个词表的 logits。」正文、图注和配图用同一写法。
