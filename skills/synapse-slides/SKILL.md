# Slides

Build the deck around what the audience needs to understand or decide. Before setting a page order, identify the audience, presentation context, available time, delivery format, and the point the audience should take away. Keep the user's existing template or format when revising a deck.

| Deck | Organize around |
| --- | --- |
| Technical talk or paper presentation | Problem and stakes → mechanism or contribution → evidence → where the result applies |
| Teaching or training | Learning objective → worked example → guided practice → check for understanding |
| Project update or decision review | Current situation → evidence and trade-offs → decision or next action |
| Demo | Audience task → walkthrough → observable result → next step |

Use one main idea per slide. Put supporting detail in notes, an appendix, or linked sources when the audience does not need it on screen. Set the page count and detail level from speaking time and the complexity of the material.

Read [the deck workflow](WORKFLOW.md) to choose a template and produce the requested format. Use [Pretext](PRETEXT.md) when the selected HTML template needs text measurement or animation. Use [Synapse](../synapse/SKILL.md) if the same assignment also needs an article or motion assets.
