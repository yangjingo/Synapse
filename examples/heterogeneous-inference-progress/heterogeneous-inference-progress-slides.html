03 / Trend

解耦演进：从“整机副本”到“算子角色”

  • 2023–2024 / 共置阶段：Continuous Batching、PagedAttention 提高单副本效率，但 Prefill 干扰 Decode。
  • 2024–2025 / PD=PDD：DistServe、Mooncake、分离式系统把 Prefill 与 Decode 拆到独立池。
  • 2025–2026 / 自适应 PD：semi-PD、PPD、Phasor 让 Prefill/Decode 的比例与扩缩成为在线决策。
  • 2026 / AFD 与 EPD：Attention/FFN 与 Encode-Prefill-Decode 解耦，算子与阶段成为新调度对象。

04 / Trend

PD / PDD：用阶段专用化换取 SLO 隔离

  • Prefill：输入并行度高、矩阵计算密集，主要影响 TTFT，适合高吞吐低成本池。
  • Decode：逐 Token、KV 常驻、带宽敏感，主要影响 TPOT，适合 HBM 资源强的池。
  • 收益条件：模型足够大、输入足够长、P:D 配比合理，并且 Prefill 干扰是主要瓶颈时收益最大。
  • 隐藏成本：KV 传输、排队、尾延迟与故障恢复开销，决定最终净收益。
「 PD 不是默认答案，阶段错配成本必须大于交接成本。 」

05 / Trend

Phasor：PD 之后，瓶颈变成动态控制

  • 静态分池问题：长 Prompt 堆积在 Prefill，Decode 可能因 KV 断粮出现假空闲。
  • P / D / M：三池模型把计算与内存余量投影到统一虚拟自由度。
  • 三时间尺度闭环：路由（微秒）、去碎片（毫秒）、扩缩（秒）联动。
  • 证据边界：多数公开结论来自局部规模；跨厂商异构仍未系统化。
「 从“能不能分”到“谁在何时接管”，是控制面的核心。 」

06 / Trend

AFD：把 Decode 再拆成 Attention 与 FFN

  • Attention / A：KV 重、带宽与容量敏感，按上下文阶段变化明显。
  • FFN / F：GEMM、MoE Experts 计算密集，适合聚合大 Batch。
  • 新增代价：A↔F 每层每步传 Activation，通信频率远高于 PD 的一次 KV 交接。
  • 核心结论：A:F 配比、互连拓扑和 SLO 决定收益；错配会引发同步等待。
「 AFD 不只是“拆”，是把资源角色重映射到最适合芯片。 」

09 / Commercial

资源与运行时：先解决“卡怎么管、模型怎么跑”

  • Dynamia / HAMi：设备注册、算力切分、隔离与拓扑调度，生态清晰。
  • OrionX / TensorFusion：前者偏 GPU over IP，后者偏开源远程 GPU 与显存池化。
  • XCoreSigma / Chitu：算子转译与国产芯片性能工程；共享 IR 与统一状态仍需验证。
  • 边界：能否把任务交给“可跑系统”不等于能解决 KV 语义一致性与故障恢复。

11 / Open Source

社区开源栈：控制、调度、执行与传输解耦

  • Resource：Kubernetes + HAMi 做设备发现、共享、切分与配额。
  • Serving：llm-d / Dynamo 负责 Router、前缀与负载感知、P/D 编排。

  • Data Plane：Mooncake / NIXL / LMCache 负责 KV 搬运与多层缓存。
  • Backend：CUDA、ROCm、Ascend、TPU、XPU、Gaudi 等继续下沉硬件差异。

12 / Open Source

Connector 已多样化，Canonical KV 仍未统一

  • SGLang：提供丰富后端扩展，Connector 已是关键边界。
  • NIXL：CPU/GPU 内存、文件、块与对象存储接口统一，网络后端可插拔。
  • Mooncake：以 KVCache 为中心拆分 Prefill/Decode 与分布式缓存。
  • 未解决：搬运能力不足以替代统一 dtype、layout、元数据与错误语义约定。

15 / Takeaways

三条线，收敛成一个研发判断

  • A1（趋势）：PD/PDD 成为主流，Phasor/PPD 做动态控制，AFD/ODS 推进算子协同。
  • A2（商业）：资源池化与副本路由已产品化，跨厂商单请求协同仍待更强证据。
  • A3（开源）：控制面与数据面可组合，统一状态与失败语义仍是核心缺口。
「 先可观测，再可交接，最后才值得拆得更细。 」
